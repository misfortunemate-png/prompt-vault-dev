# prompt-vault M1 配線報告

作成日: 2026-08-18 ／ 作成者: クリーデ（PM）

## 経緯

prompt-vault M1は、コード実装・PM検査までは合格していたが、tailscale配線で躓いて完了できなかった。当初の配線設計は「443ポートにパスで同居」する方式（`tailscale serve --set-path /vault http://127.0.0.1:8789`）で、chat-pwaと同じ443を共有する想定だった。

前回チャットでこの配線が動かず、rag-systemの配線問題と合わせてポストモーテムを実施。NW台帳とNW配線ガイドラインが策定され、prompt-vaultの配線問題はNW-1（ポート衝突）・NW-2（443パス同居問題）として起票され、PM席に差し戻された。

本チャットでNW台帳・ガイドラインを確認し、仕様を再検討して解決した。

## 症状

1. tailscale serveで`--set-path /vault`を設定してPixel 10からアクセスしても、prompt-vaultの画面が表示されなかった
2. 配線方式を専用ポート8445に変更しコードを改修した後、Pixel 10からアクセスすると「Blocked request. This host ("fraine.tail204746.ts.net") is not allowed.」と表示された

## 原因

**症状1**: `tailscale serve --set-path /vault` はリバースプロキシとして動作し、パスプレフィックス `/vault` を除去してからバックエンドに転送する。ブラウザが `/vault/api/healthz` をリクエストすると、Express側には `/api/healthz` として届く。しかしExpressは `app.use('/vault/api', api)` で待ち受けていたため、どのルートにもマッチしなかった。

**症状2**: Vite 5以降のセキュリティ機能により、dev serverは `localhost` 以外のHostヘッダーをデフォルトで拒否する。tailscale serveは `fraine.tail204746.ts.net` というホスト名でプロキシするため、Viteがブロックした。PGのlocalhost確認では現れず、tailnet経由の実機テストで初めて発覚した。

## 解決

発注者裁定（2026-08-18）により以下の方針で確定。

- 443パス同居を廃止し、専用ポート8445（tailnet専用serve）に変更。Funnelなし（個人用のためインターネット公開不要）。C-SERVE-PORTSによりFunnel 3ポート制限の対象外（mkb-reader 8444で実証済み）
- ベースパス `/vault/` を撤去しルート `/` に変更。専用ポートなのでパスで区別する必要がない
- vite.config.jsの `server.allowedHosts` に `fraine.tail204746.ts.net` を追加
- start-all.batをv10に改訂（prompt-vault起動＋serve 8445追加、mkb-readerポート台帳整合）

## 結果

- Pixel 10から `https://fraine.tail204746.ts.net:8445/` でprompt-vaultの画面表示を確認
- NW台帳: ポート8445・8789ともにverified: true
- M1仕様: v1.3に改訂済み
- NW-1・NW-2: クローズ
