## PG運用規律（定型・全フェーズ共通）

1. **停止条件**: 仕様にない判断が必要／仕様どおりだと問題が生じる／技術的に実現困難または難航／セッション外プロセスの停止等の副作用がある操作。原因判明時は「原因X・対策Y・実行可否」で報告し指示を待つ
2. **支給物改変禁止**: PM支給物はdiffゼロで検収される。技術的整合の調整もPMへ差し戻す
3. **発注者指示による仕様外修正**: 発注者から直接指示を受けた修正は実施・効果確認してよい。報告時に「発注者の指示により実装/修正」と明記する。権威文書は書き換えない
4. **着工前**: `git pull` → inspect実行（マニフェスト照合・版確認）。緑でなければ着工しない

## 作業手順

### Step 1: データモデル＋サーバーAPI

1. `data/cards.json`・`data/presets.json` の初期生成ロジックをserver.jsに実装（仕様 §2.1〜§2.3）
2. カード・スロットCRUD API を実装（仕様 §6.1）
3. プリセットCRUD API を実装（仕様 §6.2）
4. 保存API `/api/save` をM3形式に改訂（仕様 §6.3）。リクエスト形式: `{ filename, seed, folderSegments[], filenameSegments[] }`。ファイル名は `{filenameSegments_連結}_{seed10桁}.png`。M2の `character`/`outfit` パラメータは廃止
5. danbooruタグ検索API `GET /api/tags/search?q=` を実装（仕様 §6.4）。起動時に `docs/supplied/danbooru-filtered.csv` をメモリ読み込み。CSVフォーマット: `tag名,rating,post_count,aliases`。検索は tag名 に対する前方一致・大文字小文字不問・`_`とスペース同一視。最大20件返却
6. M2データマイグレーション（仕様 §8）。起動時判定: `VAULT_ROOT/presets.json` あり かつ `data/cards.json` なし → 変換実行 → `.bak` リネーム

### Step 2: テンプレートタブ

1. `src/screens/TemplateScreen.jsx` を新規作成。サブナビ（カード/プリセット切替）を含む（仕様 §3.1）
2. カード管理ビュー: スロット一覧（仕様 §3.2）→ カード一覧（§3.3）→ カード編集（§3.4）の3階層ナビゲーション。パンくずで戻る
3. スロット操作: 追加・改名・パス設定（useAsFolder/useInFilenameチェックボックス）・削除・ドラッグ並替え（§3.2）
4. カード操作: 追加・編集（positive/negativeテキストエリア）・複製・削除（§3.3, §3.4）
5. プリセット管理ビュー: プリセット一覧（タグフィルタ＝§3.5）→ プリセット編集（スロット別カード選択＋名前＋タグ＋結合プレビュー＋保存先プレビュー＝§3.6）
6. `src/components/TagInput.jsx` を新規作成（プリセットのタグ入力。既存タグサジェスト＋自由入力＋Enter確定＋×削除）
7. App.jsx: テンプレートタブの `PlaceholderView` を `TemplateScreen` に差し替え

### Step 3: 生成画面改訂

1. GenerateScreen.jsx: M2の固定4プルダウン（characters/situations/outfits/extras）を、`GET /api/cards` のスロット定義に連動する動的プルダウン群に差し替え（仕様 §4.1）
2. プリセット選択プルダウン: `GET /api/presets` から取得。選択時に全スロットのカードを一括セット。個別スロットの変更は可（§4.1）
3. プロンプト合成を改訂: 選択カードのpositive同士・negative同士をそれぞれ独立にカンマ結合（§4.2）。確認・編集欄は正・負を独立テキストエリアで表示。ここでの編集は一時的（カードに反映しない）
4. **インラインカード編集**（§4.3）: 各スロットプルダウンの右に✏️アイコン。タップでプルダウン直下にpositive/negativeテキストエリアを展開。ボタン行: 「上書き保存」（PUT /api/cards/card/:id）/ 「新規カードとして保存」（名前入力ダイアログ→POST /api/cards/card）/ 「キャンセル」。保存後にプロンプト合成を再計算し領域を閉じる
5. 保存ボタン: `POST /api/save` に送る形式を §6.3 に合わせる。seed値はgenerate応答から取得済みのものを使用
6. `src/components/TagSuggest.jsx` を新規作成。カード編集のpositive/negativeテキストエリアとインライン編集の両方で使用（§9）。カーソル位置のカンマ区切りトークンを取得→2文字以上でデバウンス300ms→`GET /api/tags/search?q=`→ドロップダウン最大10件→タップで置換＋`, `付加

### Step 4: トースト改善

1. Toast.jsx: success/infoトーストに10秒後の自動フェードアウトを追加。CSSトランジション（opacity 0.3s）。errorは手動消去のまま（仕様 §10）
