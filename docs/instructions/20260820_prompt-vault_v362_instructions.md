### #1 ビューア速度改善（サムネイル先行＋前後プリロード）

**サムネイル先行表示**: ImageViewerで画像を開いた瞬間にまずサムネイル（`/api/thumbs/{hash}.webp`）を表示し、バックグラウンドで原寸画像をロード。原寸ロード完了後に差し替える。

実装:
- `<img>` のsrcを最初はthumbUrlに設定
- `new Image()` で原寸URLをプリロード → `onload` でsrcを差し替え
- 差し替え時のちらつき防止: opacity transitionなど

**前後プリロード**: 現在の画像を表示中に、前後1枚ずつの原寸画像を `new Image()` でプリロードする。

実装:
- currentIndex変更時に `images[currentIndex - 1]` と `images[currentIndex + 1]` の原寸URLを `new Image().src` に設定
- ブラウザキャッシュに入るので、スワイプ時に即表示される

### #2 台詞の画面表示

ビューアでセリフを画像とともに視覚的に表示する機能。2つのモードを実装する。

#### §2.1 表示モード

**余白モード（既定）**: 画像のアスペクト比とビューア領域から余白を自動判定。
- 縦長画像（portrait）→ 画像の右余白に縦書きで表示
- 横長画像（landscape）→ 画像の下余白に横書きで表示
- 位置指定は不要（自動配置）

**画像内モード**: 画像の上にテキストをオーバーレイ表示。ユーザーがタップで位置を指定する。

#### §2.2 台詞編集UIの拡張

既存のセリフ編集エリア（ImageViewer内）を拡張する。

- **テキスト入力**: 既存のテキストエリア（変更なし）
- **表示モード選択**: 「余白」/「画像内」トグル
- **画像内モード時の位置指定**:
  - 画像上にタップ → タップ位置にテキストをプレビュー配置
  - ドラッグで位置を微調整
  - 位置は%座標（x%, y%）で保存
- **スタイル設定**（画像ごと）:
  - フォントサイズ: 小/中/大（14px/20px/28px）
  - 文字色: 白/黒/ピンク/カスタム（カラーピッカー）
  - 縁取り: あり/なし（既定あり。視認性向上）

#### §2.3 デフォルトスタイル（設定画面）

SettingsScreen.jsxに「台詞表示」セクションを追加:
- 既定表示モード: 余白/画像内
- 既定フォントサイズ: 小/中/大
- 既定文字色
- 既定縁取り: あり/なし

`data/settings.json` の `captionStyle` に保存。画像ごとのスタイルは未設定時にこのデフォルトを使う。

#### §2.4 DBスキーマ拡張

`images` テーブルに `caption_config` カラムを追加（TEXT・NULL可・JSON文字列）:

```json
{
  "mode": "overlay",
  "x": 75,
  "y": 20,
  "fontSize": "medium",
  "color": "#ffffff",
  "outline": true
}
```

- `mode`: `"margin"` or `"overlay"`
- `x`, `y`: 画像内モード時の%座標（0-100）。余白モードでは不要
- `fontSize`: `"small"` / `"medium"` / `"large"`
- `color`: hex色コード
- `outline`: 縁取り有無

マイグレーション: 起動時にカラムが存在しなければ `ALTER TABLE images ADD COLUMN caption_config TEXT` を実行。

#### §2.5 API拡張

既存の `PUT /api/gallery/image/:hash/caption` を拡張:

```json
{
  "caption": "台詞テキスト",
  "captionConfig": { "mode": "overlay", "x": 75, "y": 20, ... }
}
```

captionConfigはオプション。省略時は既存のcaptionのみ更新（後方互換）。

#### §2.6 レンダリング

ImageViewerの画像表示領域に、captionとcaption_configに基づいてテキストを描画する:

**余白モード**:
- 縦長画像: 画像の右に `writing-mode: vertical-rl` でCSS描画
- 横長画像: 画像の下に横書きでCSS描画
- 余白の幅は文字数に応じて自動調整（max 30%）

**画像内モード**:
- `position: absolute` で `left: {x}%`, `top: {y}%` に配置
- `text-shadow` で縁取り（outline=true時）
- `transform: translate(-50%, -50%)` で中央揃え

### #3 カード一覧リデザイン

TemplateCardList.jsx のカード一覧（スロット選択後の画面）を全面リデザイン。

**カード行のレイアウト**（モックアップ準拠）:

```
[2×2サムネ] [カード名（太字）          ] [編集] [コピー]
[         ] [正プロンプト2行…          ] [削除]
[         ] [負プロンプト2行（橙色）…   ]        [N枚]
```

- **左**: 2×2サムネイルグリッド（各42px）。このカードで生成された画像の最新4枚。DBの `prompt` LIKE検索またはカード名一致で取得。0枚のカードは空グレーセル
- **中**: カード名（太字）→ 正プロンプト（グレー・2行`-webkit-line-clamp`）→ 負プロンプト（橙色・2行省略。短ければ詰め）
- **右**: 編集/コピー/削除の直接ボタン（⋯メニュー完全廃止）＋採用枚数

**サムネイル取得API**: `GET /api/gallery/by-card?slotId={slotId}&cardName={name}&limit=4` を新設。DBの `prompt` に `cardName` のpositiveを含む画像を返す。精密な一致は難しいため、カード名 + スロットID をキーにした簡易マッチングで十分。

あるいは、生成時に `card_ids` をDBに記録する方式でもよい（ただし既存画像には遡及しない）。PGの判断で合理的な方を選択し、報告で方式を明記すること。

### #4 プリセット一覧リデザイン

TemplatePresetList.jsx を全面リデザイン。

**プリセット行のレイアウト**（モックアップ準拠）:

```
[2×2サムネ] [プリセット名（太字）         ] [編集] [コピー]
[         ] [タグチップ                   ] [削除]
[         ] [キャラ:A／衣装:制服／シチュ:…]        [N枚]
[         ] [→ キャラA/制服_{seed}.png    ]
```

- **左**: 2×2サムネイルグリッド。このプリセットで生成された画像（`preset_id` 一致）の最新4枚
- **中**: プリセット名 → タグチップ → スロット別カード割当（`スロット名:カード名` をスラッシュ区切り）→ 保存先パスプレビュー（monospace・`→` 接頭）
- **右**: 編集/コピー/削除の直接ボタン＋採用枚数
- ⋯メニュー完全廃止

### #5 プリセット編集画面リデザイン

TemplatePresetEdit.jsx を全面リデザイン。

**レイアウト**（モックアップ準拠）:

1. **プリセット名**: テキスト入力
2. **タグ**: TagInput（既存コンポーネント）
3. **スロット別カード選択＋F/N＋並び順**:
   - 各スロット行: `[▲▼] [スロット名] [カードプルダウン] [F○] [N☐]`
   - ▲▼でスロットの並び順を変更
   - F/Nチェックボックス
4. **合成プロンプトプレビュー**: 正・負それぞれ表示（カード選択に連動してリアルタイム更新）
5. **保存先プレビュー**: F/N設定に連動（例: `キャラA/制服_{seed}.png`）
6. **保存/キャンセルボタン**: 画面下部に明示配置

### #6 プリセットにスロット構成を保存

プリセットのデータモデルを拡張する。

`data/presets.json` の各プリセット:

```json
{
  "id": "p_m1n2o",
  "name": "キャラA 放課後",
  "tags": ["日常"],
  "cards": { "s_a1b2c": "c_x1y2z", ... },
  "slotOrder": ["s_a1b2c", "s_d3e4f", "s_g5h6i", ...],
  "folder": "s_a1b2c",
  "filename": ["s_d3e4f"]
}
```

新規フィールド:
- `slotOrder`: スロットIDの配列。プリセット読込時に生成画面のスロット並び順を上書き
- `folder`: Fフラグが付いたスロットID（1つのみ。nullなら「その他」フォルダ）
- `filename`: Nフラグが付いたスロットIDの配列（0個以上）

**生成画面でのプリセット読込時**: cards＋slotOrder＋folder＋filenameをすべて反映し、生成画面を完全再現する。

**後方互換**: 旧プリセット（slotOrder/folder/filenameがない）は、現在のスロット設定をそのまま維持する。

---

### #7 F排他制御

**Fは1スロットのみ**。2つ目のFをONにしたら、前のFが自動的にOFFになる。ラジオボタン的な動作。

**Nは複数可**。制約なし。

**確認・修正箇所**:
- **生成画面**: 現在のF/Nチェックボックスが排他制御されているか確認。されていなければ修正
- **プリセット編集画面**: 同上
- **保存API**: folder値が複数スロットを指していないかバリデーション
