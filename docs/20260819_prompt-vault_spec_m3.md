# Prompt Vault M3 仕様書 v1.0

文書種別: 権威文書
作成日: 2026-08-19 ／ PM: クリーデ ／ 根拠: 要件定義v1.3 R-1（カード合成）、M3要件定義（2026-08-19承認）

## §1 スコープ

M3 = スロット定義（ユーザー定義制）→ カードCRUD → プリセット（タグ分類）→ 生成画面のカードベース合成への切替 → テンプレートタブUI → M2データマイグレーション → danbooruタグ予測変換 → トースト改善。

- In: 上記すべて
- Out: ジョブキュー（M5）、ギャラリー本装（M4）、SQLite（M4）、サムネイルキャッシュ（M4）

## §2 データモデル

M1仕様 §3.1の計画に従い、M3で `data/cards.json`（スロット＋カード）と `data/presets.json`（プリセット）を導入する。VAULT_ROOT/presets.json（M2形式）はマイグレーション後にリネーム保全する（§8）。

### §2.1 data/cards.json

```json
{
  "version": 1,
  "slots": [
    {
      "id": "s_a1b2c",
      "name": "キャラクター",
      "order": 0,
      "useAsFolder": true,
      "useInFilename": false
    },
    {
      "id": "s_d3e4f",
      "name": "衣装",
      "order": 1,
      "useAsFolder": false,
      "useInFilename": true
    }
  ],
  "cards": [
    {
      "id": "c_x1y2z",
      "slotId": "s_a1b2c",
      "name": "キャラA",
      "positive": "girl, blue hair, red eyes",
      "negative": ""
    }
  ]
}
```

**slots フィールド:**

| フィールド | 型 | 説明 |
|---|---|---|
| id | string | `s_` + ランダム5文字hex。一意 |
| name | string | 表示名。初期値は §2.3 参照 |
| order | number | 表示順（0始まり）。ドラッグ並替え対応 |
| useAsFolder | boolean | 保存先フォルダ名に使うか |
| useInFilename | boolean | 保存ファイル名に含めるか |

**cards フィールド:**

| フィールド | 型 | 説明 |
|---|---|---|
| id | string | `c_` + ランダム5文字hex。一意 |
| slotId | string | 所属スロットID |
| name | string | カード名（表示名兼パスセグメント） |
| positive | string | 正プロンプト |
| negative | string | 負プロンプト（空欄可） |

### §2.2 data/presets.json

```json
{
  "version": 1,
  "presets": [
    {
      "id": "p_m1n2o",
      "name": "キャラA 制服",
      "tags": ["日常"],
      "cards": {
        "s_a1b2c": "c_x1y2z",
        "s_d3e4f": "c_q7r8s"
      }
    }
  ]
}
```

**presets フィールド:**

| フィールド | 型 | 説明 |
|---|---|---|
| id | string | `p_` + ランダム5文字hex。一意 |
| name | string | プリセット名 |
| tags | string[] | タグ（0個以上・自由入力） |
| cards | object | `{ slotId: cardId }` のマップ。未指定スロットはキーなし（＝「なし」） |

### §2.3 初期スロット定義

サーバー起動時に `data/cards.json` が存在しなければ、以下の初期データで生成する。

| name | order | useAsFolder | useInFilename |
|---|---|---|---|
| キャラクター | 0 | true | false |
| 衣装 | 1 | false | true |
| シチュエーション | 2 | false | false |
| 構図・品質 | 3 | false | false |
| 自由 | 4 | false | false |

初期カード・初期プリセットは空（ユーザーが作成する）。M2データがある場合はマイグレーション（§8）で移行される。

## §3 テンプレートタブ

フッター3番目のタブ「テンプレ」を押すとテンプレートタブが表示される。サブナビゲーションで2ビュー切替。

### §3.1 サブナビゲーション

テンプレートタブ上部にセグメントコントロール: **[カード]** / **[プリセット]**。既定は「カード」。

### §3.2 カード管理ビュー

**スロット一覧**（トップ）:

- スロットを `order` 順で縦リスト表示。各行にスロット名＋配下カード件数
- 行タップ → そのスロットのカード一覧（§3.3）へ遷移
- 下部に「＋ スロット追加」ボタン → 名前入力ダイアログ → 追加
- 各スロット行の右端にメニュー（⋯）: 改名 / パス設定 / 削除
  - **パス設定**: 「フォルダ名に使う」「ファイル名に含める」の2つのチェックボックス（§6のルールに基づく）
  - **削除**: 配下にカードがある場合は確認ダイアログ（「N枚のカードも削除されます」）
- スロットの並替え: 各行の左端にドラッグハンドル（☰）

**スロット追加・改名のバリデーション:**
- 空文字不可
- 同名スロット不可

### §3.3 カード一覧（スロット選択後）

- パンくず: カード管理 > {スロット名}
- スロット内のカードを縦リスト表示。各行にカード名＋positiveの先頭30文字プレビュー
- 行タップ → カード編集画面（§3.4）
- 下部に「＋ カード追加」ボタン → 空のカード編集画面（§3.4）へ
- 各カード行の右端にメニュー（⋯）: 複製 / 削除
  - **複製**: 「{元の名前} のコピー」で即時生成、編集画面へ
  - **削除**: 確認ダイアログ。プリセットで使用中のカードの場合は「N件のプリセットで使用中です」と警告

### §3.4 カード編集画面

- パンくず: カード管理 > {スロット名} > {カード名 or 新規}
- フィールド:
  - **カード名**: テキスト入力（必須）
  - **所属スロット**: セレクト（変更可能＝カードをスロット間で移動可能）
  - **正プロンプト**: テキストエリア（auto-grow・最大12行表示）。danbooruタグ予測変換つき（§9）
  - **負プロンプト**: テキストエリア（auto-grow・最大8行表示）。danbooruタグ予測変換つき（§9）
- 下部に「保存」ボタン。新規の場合は「作成」。
- 保存時バリデーション: カード名が空でないこと。同一スロット内で同名不可

### §3.5 プリセット管理ビュー

**プリセット一覧**（トップ）:

- タグフィルタ: 上部に既存タグのチップ一覧。タップでフィルタON/OFF（複数選択可・AND検索）。「すべて」チップで解除
- プリセットを縦リスト表示。各行にプリセット名＋タグチップ
- 行タップ → プリセット編集画面（§3.6）
- 下部に「＋ プリセット追加」ボタン → 空のプリセット編集画面へ
- 各行の右端にメニュー（⋯）: 複製 / 削除

### §3.6 プリセット編集画面

- パンくず: プリセット管理 > {プリセット名 or 新規}
- フィールド:
  - **プリセット名**: テキスト入力（必須）
  - **タグ**: タグ入力。既存タグのサジェスト＋自由入力。Enterで確定、×で削除
  - **スロット別カード選択**: 全スロットを `order` 順に並べ、各スロットにプルダウン（そのスロット配下のカード一覧＋「（なし）」）
  - **プレビュー**: 現在の選択に基づく結合プロンプトを表示（正・負それぞれ）。折りたたみ・既定開
  - **保存先プレビュー**: 現在の選択に基づくフォルダ名＋ファイル名パターンを表示（例: `作品名/キャラA_制服_{seed}.png`）
- 下部に「保存」ボタン

## §4 生成画面の変更

M2の固定4プルダウン（characters/situations/outfits/extras）を、スロット定義に連動する動的プルダウン群に置き換える。

### §4.1 レイアウト（改訂部分のみ）

1. **プリセット選択**（プルダウン）: `data/presets.json` のプリセット一覧。選択するとスロット別カードが一括セットされる。先頭は「（なし）」= 個別に選択
2. **スロット別プルダウン群**: `data/cards.json` のスロットを `order` 順に並べる。各プルダウンの選択肢はそのスロット配下のカード名＋「（なし）」。プリセット選択時に自動セットされるが、個別変更も可
3. **プロンプト確認・編集**（折りたたみ・既定閉）: **正プロンプト**と**負プロンプト**をそれぞれ独立したテキストエリアで表示。直接編集可
4. パラメータ・生成ボタン・結果一覧はM2のまま

### §4.2 プロンプト合成ルール

**正プロンプト**: 選択されたカードの `positive` を、スロットの `order` 順にカンマ区切りで結合。「（なし）」のスロットはスキップ。

**負プロンプト**: 選択されたカードの `negative` を、同様にカンマ区切りで結合。空文字のnegativeはスキップ。

M2ではpresetsの正プロンプト＋テキスト値の結合だったが、M3ではカードのpositive同士・negative同士をそれぞれ独立に結合する。

### §4.3 保存ボタンの変更

結果カードの保存ボタン押下時に送信するデータをM3形式に変更。`/api/save` に選択中のカード情報（フォルダ・ファイル名導出に必要なもの）を送る。詳細は §6.2。

## §5 保存先の自動導出（改訂版）

### §5.1 フォルダパス

`useAsFolder = true` のスロットから、`order` 順にカード名を取得し、`/` で連結してフォルダパスを構成する。

- 例: 「作品名」スロット（useAsFolder）で「オリジナル」、「キャラクター」スロット（useAsFolder）で「キャラA」 → `オリジナル/キャラA/`
- folderスロットのカードがすべて「（なし）」または folder指定スロットが0個 → `その他/`

### §5.2 ファイル名

`useInFilename = true` のスロットから、`order` 順にカード名を取得し、`_` で連結したのち、`_{seed10桁}.png` を付加する。

- 例: 「衣装」スロット（useInFilename）で「制服」 → `制服_2847103956.png`
- 例: 「キャラクター」と「衣装」がともにuseInFilename → `キャラA_制服_2847103956.png`
- filenameスロットのカードがすべて「（なし）」または filename指定スロットが0個 → `gen_{seed10桁}.png`

### §5.3 seed値

NovelAI APIレスポンスの seed 値（0〜2^32、最大10桁）をそのまま使用する。M2の `{YYYYMMDD}_{HHmmss}_{hex4}` サフィックスを `{seed10桁}` に置き換える。

seed値はファイル名の一意性を保証する（同一シードで異なるプロンプトは別ファイルになるため、カード名＋seedの組み合わせで十分にユニーク）。

### §5.4 パスの安全化

カード名をパスセグメントに使う際、以下の文字を `_` に置換: `/`, `\`, `:`, `*`, `?`, `"`, `<`, `>`, `|`。空文字になった場合は `unnamed` にフォールバック。

## §6 API（M3追加・変更分）

### §6.1 カード・スロット CRUD

| メソッド | パス | 用途 |
|---|---|---|
| GET | /api/cards | cards.json全体取得（slots + cards） |
| PUT | /api/cards | cards.json全体保存 |
| POST | /api/cards/slot | スロット追加 |
| PUT | /api/cards/slot/:id | スロット更新（名前・order・useAsFolder・useInFilename） |
| DELETE | /api/cards/slot/:id | スロット削除（配下カードも削除） |
| POST | /api/cards/card | カード追加 |
| PUT | /api/cards/card/:id | カード更新 |
| DELETE | /api/cards/card/:id | カード削除 |
| POST | /api/cards/card/:id/duplicate | カード複製 |

### §6.2 プリセット CRUD

| メソッド | パス | 用途 |
|---|---|---|
| GET | /api/presets | presets.json全体取得 |
| POST | /api/presets | プリセット追加 |
| PUT | /api/presets/:id | プリセット更新 |
| DELETE | /api/presets/:id | プリセット削除 |
| POST | /api/presets/:id/duplicate | プリセット複製 |
| GET | /api/presets/tags | 使用中のタグ一覧 |

### §6.3 保存API変更

`POST /api/save`（M2からの変更）:

リクエスト:
```json
{
  "filename": "tmp_1724034652_a1b2c3d4.png",
  "seed": 2847103956,
  "folderSegments": ["キャラA"],
  "filenameSegments": ["制服"]
}
```

- `folderSegments`: useAsFolderスロットのカード名をorder順に配列。空配列＝「その他」
- `filenameSegments`: useInFilenameスロットのカード名をorder順に配列。空配列＝「gen」
- `seed`: ファイル名末尾に付加するシード値

レスポンス:
```json
{
  "success": true,
  "saved_path": "キャラA/制服_2847103956.png"
}
```

### §6.4 danbooruタグAPI

| メソッド | パス | 用途 |
|---|---|---|
| GET | /api/tags/search?q={query} | danbooruタグ検索（前方一致・最大20件） |

- サーバー起動時に `docs/supplied/danbooru-filtered.csv` を読み込みメモリキャッシュ
- クエリは大文字小文字不問・アンダースコアとスペースを同一視

### §6.5 旧プリセットAPI（廃止）

M2の `GET /api/presets`（VAULT_ROOT/presets.json読み取り）は廃止する。M3では §6.2 の `/api/presets` が `data/presets.json` を返す。マイグレーション（§8）が旧データを移行するため、VAULT_ROOT側のpresets.jsonはサーバーが直接参照しなくなる。

## §7 生成画面の呼び出しフロー（改訂版）

1. 画面表示時: `GET /api/cards` + `GET /api/presets` でスロット・カード・プリセットを取得
2. ユーザーがプリセット選択 → 各スロットのカードが一括セット
3. ユーザーが個別にスロットのカードを変更（任意）
4. 「生成」押下 → 選択中カードのpositive/negativeを合成 → `POST /api/generate`（M2と同じ）
5. 結果カードの「保存」押下 → `POST /api/save`（§6.3の新形式）

## §8 M2データマイグレーション

### §8.1 トリガー

サーバー起動時に以下の条件を判定:
- `VAULT_ROOT/presets.json` が存在する **かつ** `data/cards.json` が存在しない → マイグレーション実行

### §8.2 変換ルール

M2の `VAULT_ROOT/presets.json`:
```json
{
  "presets": [{ "name": "...", "positive": "...", "negative": "..." }],
  "characters": ["キャラA", "キャラB"],
  "situations": ["放課後", "戦闘"],
  "outfits": ["制服", "私服"],
  "extras": ["雨", "夜景"]
}
```

変換先:

| M2フィールド | 変換先 | 変換方法 |
|---|---|---|
| characters[] | キャラクタースロットのカード群 | 各テキストを `name` に、positive/negativeは空 |
| outfits[] | 衣装スロットのカード群 | 同上 |
| situations[] | シチュエーションスロットのカード群 | 同上 |
| extras[] | 自由スロットのカード群 | 同上 |
| presets[] | 構図・品質スロットのカード群 | `name` → カード名、`positive` → カードpositive、`negative` → カードnegative |

- スロット定義は §2.3 の初期定義で生成
- M2の presets（「ポートレート標準」等）は構図・品質スロットに変換する理由: M2ではpresetはベースプロンプト（構図＋品質タグ）だったため
- data/presets.json は空のプリセットリストで初期化（M2にはプリセット概念がなかったため、M3プリセットは手動作成する）

### §8.3 後処理

- `VAULT_ROOT/presets.json` → `VAULT_ROOT/presets.json.bak` にリネーム
- コンソールに変換結果のサマリーをログ出力（カード数・スロット数）
- 次回起動時は `data/cards.json` が存在するためマイグレーションスキップ

## §9 danbooruタグ予測変換

### §9.1 対象UI

カード編集画面（§3.4）のpositiveテキストエリアとnegativeテキストエリア。

### §9.2 動作

1. ユーザーがテキストエリアに入力中、カーソル位置の直前のトークン（カンマ区切り）を取得
2. 2文字以上でサーバーに `GET /api/tags/search?q={token}` を送信（デバウンス300ms）
3. 結果をテキストエリア直下にドロップダウンで表示（最大10件）
4. 候補をタップ → カーソル位置のトークンを置換、後ろにカンマ＋スペースを付加
5. Escまたはテキストエリア外タップでドロップダウンを閉じる

### §9.3 データ

`docs/supplied/danbooru-filtered.csv` をサーバー起動時にメモリ読み込み。CSV形式はPMが支給物として配置済みであることを前提とする。読み込み失敗時はタグ予測機能を無効化し、ログに警告を記録。

## §10 トースト改善

M2の自動消去仕様を改訂:

| type | 自動消去 |
|---|---|
| success | 10秒でフェードアウト |
| info | 10秒でフェードアウト |
| error | 手動消去のみ（変更なし） |

フェードアウトはCSSトランジション（opacity 0.3s）で実現。タイマーはトースト追加時に開始。
